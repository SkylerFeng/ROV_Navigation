## gates 为什么先顺畅、再卡住

1. 旧带窗口实测在约26.5秒开始出现与原水池网格的非零接触冲量。碰撞位置约(1.6826,0.2259,0.9736)m，对应原水池细立杆。机器人此前平顺运动，随后被物理碰撞约束挡住。
2. 该水池网格原本设置为invisible，照样参与PhysX碰撞，却不出现在渲染深度图里；模型还存在缺失视觉瓦片。旧感知地图因此没有完整覆盖真实碰撞环境。
3. 跟踪器继续追逐按时间推进的名义参考。实际XY速度降到接近零，指令仍约0.3m/s，X向力约9N；最后规划起点与实测位置偏差约1.82m。外观上会表现为顶住结构、滑动或扭动。
4. 上游FSM从名义轨迹状态开始重规划，并曾仅按轨迹时间判断完成；这种假定在ROV受阻时不成立。

## slalom 为什么出现掉头、奇怪运动和停滞

旧实测约8～20秒出现反向行驶：运动指令与真实ROV朝向一度相差约160～180°。实际相机内参fx=641.374、图像640×360，水平视场约53.03°，半视场只有26.52°。运动方向大幅偏离机头时，前向相机无法提前看到正接近的障碍。
之后分别在约21.15秒和28.48秒与EntryBlock、OuterA发生非零冲量接触。日志出现多次紧急停止以及 `the drone is in obstacle` / `a star error`。机器人贴近障碍时，新的规划起点又处于膨胀禁入区，重试无法解决。旧记录共出现7次“突然发现障碍”紧急停止、数千次A*失败。这是由观测、转向、碰撞和重规划共同造成的状态链条。

## 修正感知后，为何仍可能停止

实际订阅 `/grid_map/occupancy_inflate` 并按EGO的0.05m网格索引查询，原目标 `(3.5,0,1)` 的格子被标为占用，机器人当前格子则为空闲。图上空白位置也可能属于机器人尺寸与余量扩张后的禁入区。该快照中目标距最近输入占用单元中心约0.3536m，小于当前0.5m XY膨胀尺度。

[实际膨胀地图与目标放大图](figures/freeze_diagnosis/goal_occupancy.png)

此外，原Gate2North北侧墙段下端y=1.3m，原水池立杆又占用门洞附近空间。完整感知后它们的膨胀区域连接，原来目测宽敞的门洞不再有同样的安全通道。在这份已观测地图上做8邻域搜索，换为已空闲的目标后仍需约13.79m路径，并绕到y≈4.325m；水域上边界最高约3.40m。该结果只证明已观测地图中的大绕行需求，未知区域不能作为实际安全通路。
进一步从USD读取实际水域多边形，给池边保留0.40m船体余量，对同一0.05m实测膨胀网格进行连通性检查：起点与更换后的空闲目标均在自由区，但水域内不存在连接路径。结果保存在 `logs/diagnostics/freeze_20261014/water_constrained_connectivity.json`。这是当前膨胀尺度与已观测地图下的结论，不等同于任意尺寸/任意姿态机器人在实体几何中都无法通过。

[水域边界与门洞连通性](figures/freeze_diagnosis/water_constrained_connectivity.png)

因此单独延长时间、加密深度采样或更换空闲目标，都不足以保证原门洞完成。没有通过调小膨胀半径来掩盖净空问题。

## 已完成的代码修复

- `tracker.py` / `tracking_control.py`：以实际将要执行的XY速度方向控制朝向；偏差超过20°时先停平移、转向，保持垂向调节；进入视野后再恢复平移。小误差位置保持时不再追逐旧偏航指令反复转动。
- 独立EGO副本FSM：实测与名义状态偏差超过0.25m时发布当前位置保持轨迹，重新从实测里程计生成全局/局部参考；任务完成检查实际目标距离。
- 目标占用检查：进入明确的 `BLOCKED_GOAL` 状态并保持。新目标回调直接启动规划，移除了嵌套spin/等待EXEC_TRAJ的循环；自动化测试验证了占用目标→有效新目标的切换。
- 仿真：把原水池碰撞网格作为渲染代理参与深度观测，物理碰撞仍保留；此为实验层覆盖，未修改师兄提供的USD资源。相机标定与控制/规划状态随运行保存。
- 面板与记录：显示规划/跟踪状态；`/rov/planner_status` 与 `/rov/tracking_status` 可区分对准方向、保持、无局部轨迹与占用目标。批量测试遇到占用目标时，保持稳定后以 `goal_occupied` 结束，记录为未到达。
- 三个启动脚本统一默认DDS实现，减少通信环境差异；轨迹服务器在退出前释放全局ROS句柄，后续GUI运行全部节点正常退出。

## 新对照场景和运行方法

当前活动场景为 `gates_clearance`，已经完成一次无窗口和一次带窗口到达验证。
相对原gates的环境变化只有：目标改为(3.5,0.4,1)，Gate2North的下端由y=1.3m提高到1.8m、上端保持2.9m，因此该墙段Y长度由1.6m变为1.1m、中心y由2.1m变为2.35m。其余障碍、速度、碰撞和0.5m膨胀配置保留。原 `gates` 场景文件逐字节保留。

每个终端先进入 `/home/ache/Coding/rov_navigation`。终端一：

```bash
bash scripts/select_scenario.sh gates_clearance
bash scripts/start_sim.sh
```

终端二：

```bash
bash scripts/start_navigation.sh
```

终端三：

```bash
bash scripts/send_goal.sh
```

若希望单终端自动启动、发送目标、记录并停止：

```bash
python3 scripts/run_suite.py --scenarios gates_clearance --gui
```

baseline/slalom的空闲目标验证：

```bash
python3 scripts/run_suite.py --scenarios baseline slalom --overrides config/experiments/gates_free_goal.json
```

`gates_free_goal.json`只覆盖目标位置，不改变场景障碍。切回 `gates` 可以复现原布局；完整感知发现原目标被占用时会显示BLOCKED_GOAL，不会把拒绝目标算作到达。

## 现在看到停止时如何判断

| 面板状态 | 含义 |
|---|---|
| ALIGNING | 正在先转向，让前向相机覆盖运动方向 |
| HOLDING | 位置保持；结合规划状态及实际目标距离判断是否到达 |
| GEN_NEW_TRAJ | 从实际位置寻找新局部轨迹，尚未生成有效结果 |
| BLOCKED_GOAL | 目标在已观测的膨胀禁入区，需要提供空闲目标 |

## 验证与数据

- 6项控制单元测试通过：倒退前先转向、转向时保持深度、速度/转向限幅、位置保持不乱转、视野外平移受限、非法参考保持。
- C++规划器集成测试通过：占用目标明确保持、替换目标可响应、静止机器人不会因名义时间流逝被判到达、偏差触发实测状态重规划。
- 仿真时钟回归通过：轨迹按/clock采样，暂停不推进，偏航值有限。
- 运行数据见 `logs/diagnostics/freeze_20261014`；源码/配置快照保存在各实验目录，修改前文件在其 `before` 目录。
- 重绘故障图：`python3 scripts/analyze_freeze.py`。图中接触事件按非零冲量标记；规划起点偏差是在每次轨迹收到时与插值实测位姿比较，不冒充连续的瞬时指令误差。

现有规划仍是固定高度的局部轨迹方法，地图主要来自前视深度并静态累积。未知区探索、动态障碍、真正的全局导引和完整水动力控制仍属于后续工作。本次实测验证了上述具体修复和净空对照，没有证明原不合适目标/原门洞已经稳定可通行。
