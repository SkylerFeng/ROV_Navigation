# 发现目标后转向：决策、规划与运动联合分析

分析运行：logs/qwen_demo_20261110_165224。时间均为仿真时钟。联合 semantic/events.jsonl、sim/plans.json、sim/controls.json、semantic/result.json；navigation.log 含规划状态迁移，但多数行没有仿真时间，不将其强行精确对齐。采用带 start_time 的实际发布样条及带 t 的控制遥测作时序证据。

## 异常方向切换

74.7 s：探索中看到目标，3 帧确认；向 Qwen 请求接近。请求对象 obj_016 的观测年龄已约 0.87 s。
77.7 s：Qwen 返回 approach；实时校验 invalid candidate。78.47 s 下一次请求时同一目标观测年龄 4.63 s，已无 approach 候选。事件记录支持目标观测丢失/过期导致候选不可用；具体遮挡或漏检原因无法仅凭这些日志确认。
81.2 s：Qwen 改选 explore，目的地 (1.875,-2.325)。82.63 s EGO 发布朝右下方的局部样条，终点约 (-0.58,-0.77)。局部轨迹终点并不一定等于远处语义目标。
84.0 s：再次确认目标，探索被中断。86.9 s 接近动作执行。88.27 s EGO 发布终点 (-3.525,1.125) 的样条，转回左侧。

这不是模型第一次看到黄色管子就主动拒绝接近，而是一次合法模型回复未通过实时观测检查，后续策略失去目标连续性。请求约 3 s 仿真延迟与约 1.7 s 现实 API 延迟可以同时存在；当前新鲜度门槛为 2 s 仿真时间。

## 结论与限制

主要问题是短时检测丢失、异步 API 后实时候选失效、探索/接近状态切换与不强制的局部恢复共同作用。EGO 确实跟随了切换后的目标；没有证据证明水流直接造成这些方向反转。日志中的 +/-180° 跨越需按圆周角解读，不可误当作瞬间转 360°。

目前仅设置 scan_completed=false 不强制重新扫描，因为 allowed_actions 仍含 explore，提示还偏好可用 approach。若要可靠恢复，应显式设置局部恢复状态、限时重观测与重新接近，并保留远探索的退出条件；不能删除新鲜度校验、伪造目标确认或无限延长时限。

时序数据见 docs/validation/qwen_turn_analysis_20261110/timeline.json 与 timeline.csv。控制样本按最近仿真时刻对齐，不是毫秒级精确同步；latest_plan 指最后已发布计划，即使悬停期间也可能是旧计划，不能当作正在执行的指令。此次仅分析与保存报告，未修改控制算法或调用 API。
