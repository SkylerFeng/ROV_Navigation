# Qwen 到达验证失败与恢复优化（2026-11-10）

## 原始问题证据

GUI 运行 `logs/qwen_demo_20261110_161150` 在 300 s 仿真时间超时，共 14 次 API 调用。第一次走北侧，验证失败后重新探索；多次重复靠近同一停靠区域。

从事件、实测轨迹与姿态控制日志重建：
- 120 s：距离最后观测表面约 1.288 m（超过 1.15 m 上限），速度 0.00052 m/s，朝向误差 0.073°；目标观测已过期。
- 157 s：距离约 0.931 m，速度 0.00010 m/s，朝向误差 0.550°；目标观测已过期。
- 197 s：距离约 1.031 m，速度 0.00006 m/s，朝向误差 0.548°；目标观测已过期。

这些距离来自最后一次可见表面估计，不是当前真值距离。原始日志没有保存各验证阶段的 RGB，无法断言目标消失具体由遮挡、外观变化还是检测漏检造成。不能把旧物体 ID 重新关联认定为唯一原因，因为当时同类黄色管子的其他轨迹也未保持新鲜观测。

重建数据：`docs/validation/qwen_recovery_20261110/original_diagnosis.json`。

## 修改

1. 每秒记录 verification：可见性、观测年龄、距离、速度、朝向误差和是否达标。保存最新验证 RGB/距离快照 verification_sensor.npz，帮助区分检测和控制问题。
2. 新鲜目标观测出现时，根据当前机体位置重新计算朝向，避免沿用旧接近点的方向。
3. 验证超时将失败接近位置加入本次任务的排除列表，随后请求重新观察（scan_completed=false），避免重复访问同一失败停靠点。
4. 接近候选与失败位置至少间隔 0.45 m，仍要求在观测到的安全可达区域、目标已观测侧和原距离范围内。不通过放宽完成标准获得成功。
5. 探索只有在目标存在可用接近候选时才被打断，避免看见目标但无可执行接近点时反复切换。
6. 提示模型优先综合 score，而不是单独最大化原始未知区域数量；score 已考虑距离、信息增益、新视角与重复访问。

调参接口：`runtime.json` 的 `exploration.approach_retry_separation_m`，默认 0.45。未更改任务 300 s 时限、成功条件、水动力或场景。

GUI 真实 API 测试及后续结果见下文；未提交 GitHub。
