## 首轮版本与失败分析

西侧与东侧首轮运行使用时序修复前版本；第三组启动时已加载时序修复。各 run 的 manifest 冻结对应代码。不能把三组当作同一版本的统计成功率。

错误提示组不仅超时，还与原始 Platform 扫描碰撞网格发生实际接触（不是新增挡板）：首次接触约 288 s，最大冲量约 0.421，最小分离 -0.0058 m。二维水池边界和矩形障碍连通性检查不能覆盖原场景所有三维碰撞细节。后续应排查该区域实测点云与碰撞网格的一致性，不能通过关闭碰撞或忽略报告来判定成功。

约 361 s 的 approach 指向 (0.21, 0.66)，接近黄色管子所在位置 (0.4, 0.9)，与实际黄色方块 (-4.5, 0.7) 相距很远。运行时从 YOLO 得到 box/yellow 检测，并非 LLM 凭空编造目标。该类别混淆与错误先验引发的无效搜索均保留，未宣称已经修复。`first_target_detection_s` 表示首次预测为目标类别/颜色，**不保证预测正确**。

下一步建议：在保持原场景布局的情况下，补充管子端面/侧面和方块遮挡的难例检测数据，增加类别冲突跨帧验证；同时处理东侧扫描碰撞网格与局部地图的一致性，再研究错误先验的区域搜索顺序。单纯增加任务超时不能解决这些问题。
